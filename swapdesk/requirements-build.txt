# Build-time only. Not needed to run from source; the build scripts under
# SwapDesk/scripts/ install this on top of requirements.txt before calling
# build.py.
#
# Kept separate from requirements.txt so that bumping the compiler and bumping
# a runtime dependency are two different commits with two different blast
# radii. A PyInstaller upgrade can change what ends up inside the binary
# without changing a single line of SwapDesk, which is exactly the kind of
# change that should be visible on its own.
#
# Hash-pinned, like requirements.txt, and installed with --require-hashes.
# This is the dependency that literally produces the shipped binary, so it is
# the one worth pinning hardest: a compromised or substituted PyInstaller
# wheel puts arbitrary code inside every release without touching a line of
# this repo.
#
# ONE file covers all three runners. pip accepts several hashes per
# requirement and matches whichever artifact it actually downloads, so the
# lines below carry every wheel for the pinned version (macOS universal2,
# manylinux, musllinux, win32/amd64/arm64) plus the sdist. An earlier comment
# here claimed a per-platform file was unavoidable; that was wrong.
#
# Regenerating after a version bump:
#   pip download --no-deps --no-binary :none: pyinstaller==<ver>
# is NOT enough, since it only fetches this platform's wheel. Pull the full
# artifact list per package from the PyPI JSON API
# (https://pypi.org/pypi/<pkg>/<version>/json) and take the sha256 of every
# non-yanked file, then verify with:
#   pip install --require-hashes --dry-run -r requirements-build.txt
#
# The transitive tree is listed explicitly because --require-hashes refuses
# to install anything unpinned, including dependencies pip resolves itself.
# macholib is macOS-only and pefile/pywin32-ctypes are Windows-only; they are
# listed unconditionally because pip skips them by marker on other platforms,
# and leaving them out breaks those two runners.
